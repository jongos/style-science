# Design reasoning implementation plan

1. Rationale-preserving contracts: carry human need, choice, requirements,
   evidence, alternatives and uncertainty without converting prose into rules.
2. Evidence-driven revision: identify affected decisions when context, rules,
   source revisions or evidence change. Preserve contradictory and absent evidence.
3. Concept translation: expose candidate interpretations of design concepts;
   do not assume one geometric proxy measures perceived emphasis.
4. Constraint-preserving repair: validate proposed fixes against all hard
   requirements and return no verified repair when appropriate.

First compare structured records with flat token-and-rule documents using ten
paired synthetic cases and Jev. Same information, questions and answer options;
only serialization differs. Do not promote structure merely because it looks
more sophisticated. See `evaluation/reasoning-screen/PROTOCOL.md`.

Only winning improvements are candidates for incorporation. Preserve aggregate
attempt counts and limitations; a winner-selected collection cannot estimate
general accuracy. Do not archive losing candidate outputs. No private inputs,
browser installation, publication or production-default change is authorized by
this plan. Using the existing authorized TypeSafe playground is separate from
browser-based validation of rendered designs.
